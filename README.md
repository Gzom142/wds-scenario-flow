# wds-scenario-flow

『ワールドダイスター 夢のステラリウム』のストーリーを、劇団ごとのメイン章と関連イベントとして可視化する個人用ビューアです。

> このサイトは非公式の個人制作・二次創作です。『ワールドダイスター』公式および関係各社とは関係ありません。

- [『ワールドダイスター』二次創作ガイドライン](https://world-dai-star.com/news/1947)
- [『ワールドダイスター 夢のステラリウム』利用規約](https://shop.wds-stellarium.com/Terms)

## 起動

```bash
npm install
npm run dev
```

Windowsでは、初回のみ `setup.cmd` を実行して依存関係をインストールし、以降は `start.cmd` で開発サーバーを起動できます。

## データ編集

- `src/data/characters.yml`: キャラクター、所属劇団、表示色
- `src/data/stories.yml`: 索引データへ追加するキャラクター、公式告知、関連楽曲などの補足情報
- `src/data/story-index.json`: 初期移行時に作成した、ID・タイトル・章・話数・イベント日付だけの索引

キャラクターIDは本プロジェクト内で管理する数値IDです。ストーリーの`characterIds`には、`characters.yml`に定義した数値IDを指定します。

劇団IDも本プロジェクト内で管理する数値IDです。シリウス=1、Eden=2、銀河座=3、劇団電姫=4とします。序章と最終章は劇団ではないため、特殊値を使用します。

`story-index.json` の `troupeId` は、単一劇団なら数値（例: `1`）、複数劇団に関連するストーリーなら数値の配列（例: `[1, 3]`）で指定できます。

`storyData.js` は読み込み時に、重複 ID、不正な公開日、未定義のキャラクターID・劇団IDを検出します。

### データの取り扱い

- 今後の追加・修正は、公式サイト、公式SNS、または通常のゲームプレイで確認できる事実を手動で整理します。
- ゲームプログラムの解析、抽出されたリソース、権利・由来を確認できないデータは更新元として使用しません。
- 台詞、音声、画像、背景、シナリオ本文など、コンテンツ本体は収録しません。
- 公開中イベントの核心に触れる情報は掲載せず、公式ガイドラインと利用規約の更新に応じて運用を見直します。
- タイトル、章番号、公開日、推奨視聴順は公式告知を優先します。

接続線は手動登録せず、各ノードの `releaseDate` と `troupeId` から自動生成します。劇団ごとに公開日順でノードを並べ、通常は前後のイベントを接続します。間にメイン章がある場合はイベント同士を直結せず、`直前の同劇団イベント → メイン章 → 直後の同劇団イベント` と接続します。同じ区間に複数のメイン章がある場合は、それぞれを直前・直後のイベントへ接続します。複数の劇団IDを持つイベントは、それぞれの劇団の時系列に含まれます。公開日が未設定のノードは自動接続の対象外です。

イベントの横位置も `troupeId` から自動計算します。単一劇団のイベントはその劇団のメイン列に置き、複数劇団のイベントは対象となる劇団列の平均位置から `layout.mixedEventOffset` の分だけずらして表示します。平均位置が中央になるイベントは、縦一列に集中しないよう `sourceId` に応じて左右へ振り分けます。

### 公式告知の登録

`stories.yml` の `overrides` に `tweetUrl` を設定すると、詳細パネルに公式X投稿を埋め込みます。URLは `https://x.com/<アカウント>/status/<投稿ID>` のような投稿本体のURLを指定してください。X投稿がなく`officialUrl`だけが登録されている場合は、公式サイトへのリンクを表示します。どちらも未登録の場合、公式告知欄は表示しません。

個人ユーザーによるストーリー概要・あらすじは掲載せず、公式告知を案内欄として使用します。

公式投稿は引用元が分かる埋め込みまたはリンクとして表示し、画像・本文をリポジトリへ転載しません。

関連楽曲は `stories.yml` の `overrides` に `musicUrl` と `musicEmbedUrl` を設定します。`musicEmbedUrl` がある場合はApple Musicのプレビューを表示し、未登録の場合は `musicUrl` のリンクだけを表示します。

## GitHub Pages

リポジトリの **Settings → Pages → Build and deployment** で **GitHub Actions** を選択すると、`main` への push 時に `.github/workflows/deploy.yml` がビルド・公開します。
